# Цифровая визитка — TypeScript backend

Backend-приложение на NestJS, GraphQL, Prisma и PostgreSQL. Запрос `profile` возвращает информацию о кандидате, навыки, опыт и проекты. Локальная среда поднимается Docker Compose, выполняет миграции и заполняет базу проверенными данными без дублей при повторном запуске.

## Запуск с нуля

Нужен запущенный Docker Desktop. Из корня проекта:

```bash
docker compose up --build
```

После сообщения о запуске откройте **http://localhost:3000/graphql**. На странице доступен Apollo Sandbox. Для проверки из терминала:

```bash
npm run smoke
```

Пример запроса в Sandbox:

```graphql
query {
  profile {
    name
    description
    githubUrl
    skills { name category }
    experience { company position period achievements }
    projects { name description url }
  }
}
```

Для остановки: `docker compose down`. Данные PostgreSQL остаются в именованном томе; повторный запуск не дублирует записи.

## Архитектура

- `src/profile/profile.resolver.ts` задаёт публичный запрос GraphQL. Он не знает, как хранятся данные.
- `src/profile/profile.service.ts` содержит чтение профиля и связь с Prisma. Профиль единственный, поэтому вложенные коллекции загружаются одним вызовом Prisma `findUnique({ include: ... })`. Нет отдельного запроса к БД для каждого навыка или проекта. Для списка профилей понадобилась бы отдельная стратегия пакетной загрузки, например DataLoader.
- `src/prisma.service.ts` создаёт один Prisma Client для приложения и управляет подключением.
- `prisma/schema.prisma` задаёт явные связи Profile → Skill / Experience / Project. Отдельные таблицы позволяют менять каждую коллекцию независимо и показывать реальные вложенные GraphQL-данные.
- `prisma/seed.ts` создаёт один профиль и связанные записи через `upsert`. Повторный запуск не создаёт дубликаты. Факты взяты из подтверждённого профиля кандидата; неподтверждённый коммерческий backend-опыт не добавлен.
- `Dockerfile` собирает приложение, а `docker-compose.yml` запускает PostgreSQL и приложение. Контейнер приложения ждёт здоровую БД, применяет сохранённую миграцию, выполняет seed и стартует сервер.

Сервис намеренно только для чтения: задание просит представить профиль, а операции записи увеличили бы объём и потребовали бы авторизации. Профиль задан постоянным ID `kirill`; если приложение вырастет до каталога людей, запрос `profile(id: ID!)`, ограничения доступа и пакетная загрузка связей станут следующими изменениями.

## Проверки и ограничения

`npm run smoke` отправляет настоящий GraphQL-запрос и проверяет наличие вложенных данных. Приложение не включает S3: эта технология есть в вакансии, но отсутствует в обязательном перечне тестового и не используется в подтверждённых проектах кандидата. Публичный деплой и удалённый Git-репозиторий пока не созданы.
